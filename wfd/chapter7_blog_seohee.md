# 7장 | 기술 블로그 쉽게 쓰고 운영하기

## 기술 블로그 쉽게 쓰는 방법 3가지
### 소재 우선 글쓰기
- 소재 의식을 갖고 쓰는 것임. 소재 의식은 특정한 대상이나 상황에 대한 자기만의 관점이나 생각이나 해결 방안을 뜻함.
- 독자와 상관없이 대상이나 상황을 마주쳤을 때부터 그 상황을 벗어나기까지의 일을 담담하게 정리하는 것임.

### 자기 수준 글쓰기
- 기술 블로그는 독자 수준이 아니라 작성자 수준으로 쓰는 편이 나음.
- 개발자가 사용하는 용어는 이미 표준이거나 관습인 경우가 많기에 쉬운 용어로 바꿔 쓰지 않아도 됨.

### 재미있는 글쓰기
- 글에 재미가 있으면 독자가 활발히 반응하고 독자의 반응이 활발하면 블로거는 글을 계속 쓸 동력을 얻음.
- 실제로 위키피디아보다는 나무위키가 읽는 재미가 있음.
- 좋은 기술 블로그는 개발자의 경험에서 우러나오는 내용을 적절한 글쓰기 기교로 녹아낸 것임.

## 글의 종류별로 목차 잡는 법| - 저술
- 기술 블로그는 크게 4가지로 나뉨.

| 구분 | 내용                             | 종류                                |
|----|--------------------------------|-----------------------------------|
| 저  | 직접 경험하고 실험한 과정이나 결과            | 개발기, 도입기, 적용기                     |
| 술  | 어떤 것을 분석하여 의미를 풀이하고 해석한 것      | 기술 소개, 용어 분석, 에러 해결 방법 등          |
| 편  | 산만하고 복잡한 자료를 편집해 질서를 부여한 것     | 프로그램 설치/설정 방법, 튜토리얼, 세미나 후기, 책 리뷰 |
| 집  | 여러 사람의 견해나 흩어진 자료를 한데 모아 정리한 것 | 명령어 모음, 팁, OO가지 규칙                |

### 저: 개발기는 목차를 잘 잡아서 본문부터 쓰자
- 개발기를 쓸 때는 목차를 잘 구성해야 함. 목차만 제대로 잡으면 다른 종류의 글보다 쓰기 쉬움.
- 여러 경험을 단방향 목차로 바꾸는 핵심은 성공한 루트와 실패한 루트를 구별하는 것임.
- 성공한 최종 루트를 쓴 다음에 실패 루트를 덧붙이면 됨.
```text
1. 머리말
    가. 서비스 설명
    나. 개발의 필요성
2. 본문
    가. 아키텍처나 알고리즘
    나. 개발 모델(최종 루트)
    다. 개발 과정에서 발견한 문제와 해결 방법(경험 루트)
    라. 남은 작업
3. 맺음말
    가. 소감이나 회고
```
- 글을 쓸 때는 머리말부터 쓰기 보다는 목차를 정하고 본문부터 쓰는 것이 쉬움.

### 술: 원전을 비교하고 실험해 풀이해서 쓰자
- 술은 어떤 것을 분석하여 의미를 풀이하고 해석한 것임.
- 개발에서의 술은 새로운 기술을 자세하게 설명한 것, 비슷한 용어를 비교해 풀이한 것, 에러 해결 방법임.
  - ex. GET과 POST 차이
- GET과 POST 차이의 목차는 다음과 같이 쓰면 좋음.
```text
1. HTTP
2. GET
3. POST
4. GET과 POST 차이
5. 참고
```

## 글의 종류별로 목차 잡는 법|| - 편집
### 편: 순서를 요약하여 쓰자
- 산만하고 복잡한 자료를 편집해 질서를 부여하며 주로 시간 순서나 작업 절차에 따라 구성함.
- 프로그램 설치 및 설정 순서, 개발 방법 튜토리얼, 컨퍼런스 후기 등을 주요 소재로 삼음.
- 본인이 한 일을 시간 순서대로 나열한 뒤 적절한 단계로 묶어 핵심 내용을 목차로 만듦.
- 독자가 전체 과정을 파악하도록 `H2`, `H3` 태그를 활용해 계층을 명확히 분리함.

### 집: 자료를 모아 핵심을 엮어서 쓰자
- 여러 사람의 견해나 흩어진 자료를 한데 모아 정리하며 핵심 요약과 간결함을 중시함.
- 코딩 팁, 추천 도서 리스트, 인터뷰 질문 모음 등 유용한 정보들을 목록 형태로 나열함.
- 본인의 경험에서 터득한 노하우를 한 줄씩 정리하는 것만으로도 훌륭한 콘텐츠가 됨.
- 초보 개발자가 도전하기 가장 쉬운 형식이며 검색 유입 독자에게 실질적인 도움을 줌.

### 편집글
- 직접적인 개발 경험을 기술하는 저술보다 접근성이 높고 기존 자료 수집만으로도 작성이 가능함.
- 특정 팁을 모은 글은 독자 선호도가 높으며 실용적 정보를 원하는 층에게 인기가 많음.
- 기술 블로그 입문자에게는 글쓰기 근육을 기르기 위해 집이나 편 형식을 우선 추천함.

## 기업의 기술 블로그 운영 팁
### 기술 블로그는 회사의 가치를 높임.
- 활성화된 블로그를 통해 우수 개발자 채용에 긍정적인 영향을 미침.
- 사내에 흩어진 개발 산출물과 문제 해결 과정을 체계적으로 기록해 기술 노하우를 축적함.
- 글쓰기 과정에서 지식을 체계화하게 되어 구성원들의 개발 역량이 함께 강화됨.

### 투자를 통한 블로그 활성화
- 블로그를 단순 기록장이 아닌 회사의 가치를 높이는 광고 매체로 인식하고 투자를 집행함.
- 홍보와 검색엔진 최적화 등 기술 블로그 운영자가 제대로 일을 할 수 있도록 비용을 투자해야 함.

### 회사의 문화를 반영하는 글쓰기
- 네이버처럼 정형화된 구성과 건조하고 간결한 문체로 세련된 느낌을 줄 수 있음.
- 우아한형제들처럼 대화하듯 자연스러운 표현과 실감 나는 구성으로 친근함을 전달함.
- 회사의 글쓰기 문화를 먼저 정의해 개발자들이 글을 어떻게 쓸 지 알 수 있게 해야 함.

### 협업해서 글쓰기, 짝 글쓰기
- 짝 글쓰기를 하면 글의 완성도가 높아지고, 지식을 보편화할 수 있으며 팀 회고, 심리적 안정감 같은 장점이 있음.
- 한 명은 쓰고 다른 한 명은 검토하며 독자 관점을 반영하는 `Driver`와 `Navigator` 방식을 사용함.
- 개발자가 초안을 쓰면 글쓰기 전문가가 조언하여 완성도를 높이는 `Coder`와 `Adviser` 방식을 활용함.
- 쓴 글을 소리 내어 읽고 상대방이 들으며 어색한 문장을 찾는 `Verbalizer`와 `Listener` 과정을 거침.
- 목차별로 번갈아 쓰거나 코드와 설명을 분담하여 작성하는 `Ping-Pong` 방식을 도입함.
